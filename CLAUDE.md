# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager: **pnpm** (lockfile is `pnpm-lock.yaml`).

- `pnpm dev` — Next.js dev server on `localhost:3000`
- `pnpm build` — production build
- `pnpm start` — run production build
- `pnpm lint` — `eslint .`

No test runner is configured.

## Project context

Marketing/portfolio site for OptimizeDeals (frontend architecture studio). Linked to a **v0** project — chats on v0 push commits directly to this repo, and every merge to `main` auto-deploys to `optimize.deals` (Vercel). When editing, assume code may be regenerated by v0 in the future; keep conventions consistent with surrounding files.

## Architecture

### Stack

- Next.js **16** App Router, React **19**, TypeScript **5.7** (strict)
- Tailwind CSS **v4** (via `@tailwindcss/postcss`, no `tailwind.config`; tokens live in `app/globals.css`)
- shadcn/ui (`new-york` style, base color `neutral`) under `components/ui/`
- Radix primitives, Framer Motion, lucide-react icons
- Path alias `@/*` → repo root (configured in `tsconfig.json` and `components.json`)

### Routes (`app/`)

App Router with route segments: `book`, `careers`, `company`, `insights/[slug]`, `labs`, `og-preview`, `products`, `solutions`. Each section uses a per-segment `layout.tsx`. Root `app/layout.tsx` sets Geist fonts, dark theme (`bg-[#000216]`), and `@vercel/analytics` (production only).

### Content pipeline

- Articles: MDX files in `content/insights/*.mdx` with gray-matter frontmatter (`title`, `description`, `date`, `author`, `category`, `tags`, `image`, `featured`).
- `lib/mdx.ts` is the only content API: `getAllArticles`, `getArticleBySlug`, `getRelatedArticles` (scores by category match + tag overlap), `getLatestArticles`, `getAllCategories`, `getAllTags`, `formatDate`. Reading time computed via `reading-time`.
- `app/insights/[slug]/page.tsx` uses `generateStaticParams` to pre-render all articles.
- **Rendering gotcha**: `components/blog/mdx-content.tsx` does **not** use real MDX compilation despite importing `next-mdx-remote`. `MDXRenderer` is a hand-rolled line-based parser that splits on `\n` and regex-matches a fixed set of constructs: headings, lists, blockquotes, fenced code, inline code/bold/italic/links, and a small whitelist of component tags (`<Image>`, `<ArticleImage>`, `<Callout>`). Other JSX in MDX will be silently dropped. When adding a new MDX-usable component, you must extend this renderer in addition to the `components` map.
- `next.config.ts` sets `pageExtensions` to include `md`/`mdx` and enables `experimental.mdxRs`, but the actual article render path bypasses MDX — these settings only matter if you add pages authored directly as `.mdx`.

### OG image system

- Edge runtime route at `app/api/og/route.tsx` (`export const runtime = "edge"`) using `next/og` `ImageResponse`.
- Composition pieces in `lib/og/` (`background.tsx`, `logo.tsx`, `typography.tsx`, `layouts.tsx`, `config.ts`). `OG_CONFIG` holds dimensions, brand colors, typography scale, spacing — duplicated from `globals.css` because Edge runtime can't read CSS vars.
- Pages: `PAGE_META` map in the route covers static segments. Articles pass `title`/`description`/`category` as URL query params (set in `app/insights/[slug]/page.tsx` `generateMetadata`) — do **not** import Node-only deps (e.g. `lib/mdx.ts`) into the OG route.
- `app/og-preview/page.tsx` is a dev aid for previewing generated images.

### Components

- `components/ui/` — shadcn primitives. Don't hand-edit unless intentional; prefer `pnpm dlx shadcn` regen.
- `components/blog/` — article shell (`article-layout.tsx`), TOC, reading progress, and the MDX rendering pipeline.
- `components/blog/mdx-components/` — the whitelist of MDX-usable components (`Callout`, `ArchitectureDiagram`, `MetricsCard`, `ArticleImage`, `QuoteBlock`, `Steps`, `ComparisonTable`, `CodeBlock`).
- Top-level marketing sections (`hero.tsx`, `services-section.tsx`, etc.) are composed by route `page.tsx` files.

### Styling conventions

- Dark theme only. Brand tokens defined in `app/globals.css` (`--brand-*`, `--background: #000216`, etc.).
- Most components use **hard-coded hex literals** (`text-[#7A8BA7]`, `border-[#002A6B]`) rather than CSS variables — match the surrounding file's style instead of introducing new tokens.
- `cn()` from `lib/utils.ts` (clsx + tailwind-merge) is the standard class composer.

## Gotchas

- `next.config.ts` sets `typescript.ignoreBuildErrors: true` — `pnpm build` will not catch type errors. Run `pnpm exec tsc --noEmit` if you need real type checking.
- Remote image hosts are restricted in `next.config.ts` `images.remotePatterns` (`optimize.deals`, `*.vercel-storage.com`, `*.giphy.com`). Add a new pattern before using a new external image host.
- `NEXT_PUBLIC_BASE_URL` overrides the default `https://optimize.deals` used for metadata and OG image URLs.
- v0 sandbox files (`__v0_*`, `.v0-trash/`, `.snowflake/`) are gitignored — don't commit them.

## Writing articles (`content/insights/*.mdx`)

- **Never use em dashes (`—`) in article prose.** They make the text read as AI-generated. Use natural punctuation instead: commas, colons, parentheses, or periods, depending on the relationship being expressed.
  - Aside or parenthetical → parentheses `(...)` or commas
  - Setup followed by elaboration → colon `:`
  - Two independent thoughts → period and new sentence
  - Loose continuation → comma
- This rule applies to article body, callout text, JSX component descriptions (e.g. `Steps`, `FeatureGrid`, `MetricsCard`), and table cells. It does not apply to code blocks, frontmatter, or CLAUDE.md itself.
- En dashes (`–`) for numeric ranges are also discouraged in prose; write "hours to days" instead of "hours–days".
